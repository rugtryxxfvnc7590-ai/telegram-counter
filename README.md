# Telegram 互推链接计数机器人

每天北京时间 0 点自动重置计数。

## 功能

- 监听指定 Telegram 群内的 X/Twitter 链接
- **收录**每条链接对应的 X 用户名与发送人电报 @（写入 `link_registry.json`）
- 保存原始消息文本、结构化 X 链接、推文 ID、发送人电报 @ 和 Telegram user id
- 一条消息里有两个 X 链接时，第一条按“互推原帖账号”保存，第二条按“回推检查账号”保存
- 每群每日名额从 `bot_reply_rules.json` 的 `daily_list_limits` 读取，初始40条、0为不限额；三个群的满额和候选回复都由后台开关控制
- **不再**每条链接私信推送给主人
- 与本地「互推检查脚本」联动：检查到漏推时，报告里附带「TA的电报号是 @xxx」
- 可选删除同步：配置 Telegram 用户账号会话后，会核查登记过的群消息是否仍存在；如果成员把整条消息删掉，下一轮运行会同步删除后台候选链接
- 每轮使用 Telegram 用户账号会话补扫群一、群二、群三当天消息，补齐 Bot API 未收到的链接
- 每轮完整收录后，满额群提前发送当日正式名单到主人私信，未满额群保留19:00流程；已发成功的群不重发，失败的群下一轮重试

## 监听的群

- `TELEGRAM_CHAT_ID`（GitHub Secret，可逗号分隔多个）
- 群一固定额外群：`-1003891628675`
- 群三固定额外群：`-1003739822194`

## 删除消息同步

普通 Bot API 不会推送“群消息被删除”的更新。要同步整条消息删除，GitHub Secrets 需要额外配置 Telegram 用户账号会话：

- `TELEGRAM_API_ID`
- `TELEGRAM_API_HASH`
- `TELEGRAM_STRING_SESSION`

19:00 私信名单还需要配置：

- `TELEGRAM_OWNER_CHAT_ID`（必须是主人个人聊天 ID，程序会拒绝把群 ID 当成私信目标）

未配置这些 Secret 时，删除同步脚本会安全跳过；编辑消息后把 X 链接删掉仍由 Bot API 直接同步删除。

## 与互推检查脚本联动

收录数据保存在仓库根目录 `link_registry.json`，互推检查脚本会自动从 GitHub 拉取当日数据，在漏推报告里附上对应电报账号。

## 每群名额和候选

后台“当日互推名单”保存并发布每群上限，“机器猫回复规则”管理文案。合格主推链接按消息先后录取，超额保留候选，第二条回推链接不计数。`daily_capacity.py` 是与后台镜像分发的纯规则模块，两边回归测试使用同一排序和筛选规则。

`send_daily_lists.py` 在用户会话补齐及删除同步之后统一计算名额、私信和候选回复。上限40时，候选阶段在43、46、49条触发；上限30时为33、36、39。第3阶段之后仍每3条触发一次。其他超额消息使用 `limit_overflow`，同一消息不叠加两条名额回复。文案支持 `{limit}`、`{count}`、`{overflow_count}`、`{group}`。

上限和录取状态随当天登记一起保存；`capacity_replies` 按日期和群记录回复成功，`owner_daily_lists` 记录私信成功及实际链接。未核实完整群快照不发名单。名额/候选回复按消息原始发送时间筛选：当日19:00前的合格链接可在任务延迟恢复后补回复一次，19:00及之后发来的链接不回复；发送失败可在当日后续轮次重试，不跨日补发旧消息。已有GitHub Actions轮询时间不变，提前发送发生在云端本轮确认满额后，不是实时消息推送回调。

## 已发送名单的编辑同步

v3.10.0起，私信发送成功后固定名单成员、编号、原群消息ID和主推X账号，并保存私信消息ID。当天原消息编辑为同账号的新帖子且新帖符合原有资格规则时，使用 Telegram `editMessageText` 更新原私信，例如 `已编辑 3 https://x.com/账号/status/新帖子ID`，条目之间仍保留空行。只有改过帖子链接的条目标记“已编辑”，重复修改继续使用原编号和同一条私信。

- 同步不受满额或19:00截止阻止，但仅限当天原名单；原消息必须发送于当天00:00至19:00前。同账号另发一条消息、不同账号、其他群、第二条回推链接，都不能替换这个位置。
- 名额配置变动、候选增加或原消息删除，不会在已发私信里补入新人；新帖不合格或来源不确定时保留原链接。群原有收录、删除和资格判断代码不变。
- 编辑成功才更新已发记录，失败下轮重试；相同内容不重复编辑，不通过另发新消息处理编辑失败。同步随现有云端轮询执行，不是实时推送，GitHub调度延迟仍可能影响到达时间。
- 旧版私信没有消息ID，默认不修改、不补发。本人确认后，可手动运行工作流，填写 `reissue_owner_group` 和当天 `reissue_owner_date` 补发一次；沿用旧私信的固定成员和顺序，不重新截取最新前N名。后续编辑这条新版，旧消息保留。日期不符或已补发的不重复补发。

Telegram接口依据：[编辑已有消息](https://core.telegram.org/bots/api#editmessagetext)。

### 换帖群内回执

v3.10.1起，已经发给本人的名单发生换帖后：

- 私信编辑成功、消息ID及新链接已写入发送记录，才向原群、原消息回复 `更换的新链接已收录`。私信更新失败或无法确认发送内容，不回复成功。
- 新帖按现有规则确认为缺少指定@或粉丝不足，并且旧链接仍在已发私信中，回复 `此编辑后的新链接违规，不予收录，已收录原本旧链接`。未知质量不冒充违规；已入选换帖改走这条专用回复，不叠加普通违规提醒。
- 两种回执只在北京时间00:00至19:00前发送，每条发送前检查当前时间。19:00至23:59群内静默，但私信编辑照常；未发的旧日回执不跨日补发。
- 状态保存在 `state.json` 的 `edited_link_receipts`，按天分群记录原消息及换帖结果；成功后不重复发。群回复失败只重试回复，编辑后的原消息已删除时也不会另发无关联消息。

版本说明：本仓库机器猫版本读取 `VERSION_COUNTER_BOT`；本地互推检查/自动转帖后台版本读取其独立项目的 `VERSION_REPOST_LIST`。两者独立升级，后台显示v3.9.0不表示云端机器猫仍是旧版本。
